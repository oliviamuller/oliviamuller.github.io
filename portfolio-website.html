How I built it

Using AI to build, iterate, and learn

  1. 01

    Start with a simple prompt

    I began in Cursor with a broad request to create a GitHub Pages website for my resume and projects. I knew coding fundamentals, but I wanted to see how generative AI could help turn an idea into something functional.

  2. 02

    Learn to direct the AI

    The early versions showed me that my prompt was too broad. I learned to provide clearer goals, background, content, structure, design preferences, and constraints so the output needed less back-and-forth.

  3. 03

    Build and iterate

    I treated the generated site as a starting point, not a finished product. I revised the navigation and styling, added case studies, updated my resume, and used the Git history to track how the project changed.

  4. 04

    Expand my AI toolkit

    Working in Cursor made me more aware of token use and context. I added OpenAI Codex to compare workflows and learned that clear requirements matter across tools.

  5. 05

    Learn Git and GitHub

    Git was not part of my coding courses, so I learned it while building. My mom first walked me through repositories, branches, commits, and pull requests; then I adapted that workflow for a project I maintain myself.

  6. 06

    Question the traditional workflow

    AI tools let me begin building before I understood every part of a professional workflow. I still had to review the work and make decisions, but the process made me curious about which development steps may become automated.

  7. 07

    Keep building

    The website continues to change as I complete projects and develop new interests. What began as an AI-assisted coding experiment has become a broader lesson in development, design, iteration, and storytelling.

What I learned

AI moved faster, but I still made the decisions

Better prompts produced better results. Clear goals, useful context, and specific constraints helped the tools understand what I wanted and reduced unnecessary revisions.

AI accelerated the coding, but it did not replace my role. I still had to evaluate the output, notice problems, troubleshoot, and decide what should change.

Longer sessions also taught me that context matters. I became more aware of token use, context windows, and how focused instructions improve both the quality and efficiency of the work.

It made me wonder how much of today's standard development workflow will still be standard five years from now.
